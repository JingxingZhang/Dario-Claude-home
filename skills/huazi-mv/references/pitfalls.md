# 常见问题与检查清单

## 预览时逐张检查
- 字出画面：长句、`spread` 样式、`vert` 竖排太长（竖排每列最多约 8 个字）。
- 字和贴纸、标签互相压住：标签默认在句末右上角，句子很长时会挤到右边缘。
- 暗场景里花字不够亮：用带光晕的 `storm` / `night` 配色，不要用 `memory` / `dusk`。
- 亮场景里花字发灰：填充色和背景太接近时换配色，或加重外描边颜色。
- 两句同时出现：前一句的 `hold` 太长、下一句来得早；竖排以外的句子不要设 `keep`。
- 过渡生硬：`PAL_KEYS` 相邻两项时间太近（< 1 秒）。

## 音源与时间轴
| 现象 | 原因 | 办法 |
|---|---|---|
| 换音源后整首歌的时间都偏了同样的秒数 | 两个音源开头静音长度不同 | `align_lines.py` 会算出偏移，整体平移 |
| 前半段对得上，后半段对不上 | 其中一个音源是剪辑版或拼接版（短视频平台常见），结构不同 | 看 `align_lines.py` 输出的 candidates 和“时间倒退”提示，按目标音源的真实结构重排段落，缺的段落（间奏、solo）补画面 |
| 某句置信度 < 0.95 | 这句旋律和别处很像，或伴奏变化大 | 用前后句的间隔推算，并在交付时提醒用户确认这一句 |
| 测出的 BPM 是体感的两倍 | librosa 对慢歌常见 | `analyze_audio.py --half auto`（默认）会自动取一半 |
| 标着 Hi-Res 的文件频谱在 22 kHz 截断 | 44.1 kHz 升频来的 | 照常能用，告诉用户这不是真高解析度 |

## 渲染与交付
| 现象 | 原因 | 办法 |
|---|---|---|
| `import skia` 报 libEGL 找不到 | 系统缺图形库 | `setup.sh` 会装 libegl1 / libgl1 |
| 字体下载失败 | GitHub Releases 可能被网络策略拦住 | `setup.sh` 用的是 raw.githubusercontent.com 上的 Google Fonts，换网络或手动放进字体目录 |
| 英文字体里的中文显示成方块 | Cormorant Garamond 没有中文字形 | 中文用 `kl` / `sb` / `s6`，英文用 `ci` |
| 对话里发的成片，用户下载不了 | 文件太大 | 用下载页：`split_upload.py` 切块 → 上传 → `build_page.py` 生成页面 |
| 下载页里的 `<a download>` 链接点了没反应 | 页面运行在沙箱里 | 模板用的是页面自带的“保存文件”能力，不要改回普通链接 |
| 成片想保留无损 | AAC 是有损的 | `render_all.py --audio alac`（苹果设备直接播放；Windows 部分播放器不支持），或两个版本都给 |
| 成片体积太大 | 雨线、颗粒很吃码率 | 调高 `--crf`（22 → 24 约小 30%）；不要为了体积牺牲 1080p |

## 版权与发布
- 歌词只用用户提供的文件，不凭记忆补全或默写。
- 用户的 GitHub 仓库如果是公开的，歌词、音频、字体、成片都不要提交，只提交代码。
- 公开发布前提醒用户：音乐有版权，简介写明原唱和“二创”，不要写成官方作品。
