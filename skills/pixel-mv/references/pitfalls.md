# 检查清单与踩过的坑

## 每轮关键帧都要过一遍
0. **是这首歌的样子吗**：人物、配色、场景、节奏换到别的歌上也说得通吗？说得通就说明还在“套模板”，回到 visual-design.md 重做。
0.5 **贴主题吗**：人设、关系、自编梗、结局有没有违背「创作背景与主题」？（踩过的坑：《晚安》写的是暧昧，却从“多情人”“见异思迁”推出“对方花心、群发晚安”，还把结局改成让对方难堪。）
0.55 **是一个完整的故事吗**：只看画面不看歌词，能看出开场、发展、转折、结局吗？结局和开头相比有变化吗？每句画面是否对应 `故事.md` 节拍表里的那一步？
0.58 **重复的歌词画面都不同吗**：把同一句歌词的几遍并排放在拼图里比较。构图可以押韵，但人物状态、时间、道具或结果必须变，而且变化是故事的推进。`sweep.py` 报“镜头用了 N 次”或“回放镜头”就是没做到。
0.6 **贴精读吗**：每句画面是否对应 `歌词精读.md` 里这句的意象和潜台词？有没有用了精读里标为“要避开”的画法？结尾是否顺着最后一句（及被改动的字）走？
1. **画面贴词**：每句中段那一帧，不看歌词也能大致猜出唱的是什么。
2. **遮挡**：像素字和道具在 y<120（原生坐标），不压歌词花字、署名、人物的脸；气泡不出画面（`say` 会自动往回推）。
3. **小字清晰**：`scale=1` 的像素字只描一圈深色边（库里已处理）；拼图缩小后看不清的字放到 `scale=2`，或者删掉。
4. **方向一致**：人物朝向、视线、风向、旗子、船或车的运动方向互相说得通（东北风向左吹，火船就得往左开）。
5. **动作不穿模**：比心、挥手的手臂别从脸上穿过（库里比心已绕开）；举牌别挡住头。
6. **转场**：镜头切换处有 0.16 秒像素溶解；段落切换处（`SECTIONS`）有玻璃透镜横扫；同一场景连续几句时，背景卷动位置要接得上。
6.4 **光影层**：户外和室内场景画完背景后有没有调用 `ST.mark(img)`？没调用就没有景深和轮廓光；在人物之后才调用，人物会被一起虚化。
6.5 **玻璃层**：玻璃上的字在全分辨率下看得清（`mv.frame(秒).crop(...)` 截局部看）；不放在太阳、强光正上方；同屏玻璃元素（不含歌词托盘和署名）不超过 3 个；“常驻”的玻璃用 born=None，不要用很早的时刻冒充（超过 99 秒会被当成过期而消失）。
7. **第 0 帧就是封面**：歌名、原唱、画面都已到位。
8. **片尾**：歌名、原唱、谢谢收看都在，最后 1 秒淡出到黑。

## 写代码时
- **动作一律按 `lt` 写**：重复段复用镜头时，写死的绝对秒数会错位。
- **随机一律用 `hsh()`**：用 `random` 每帧结果不同，画面会闪。
- **打字机效果**：气泡刚出现那一刻只有一个字，导出的帧看到“O”“喂”之类的半截不是 bug。
- **花字分两遍画**（库里已处理）：先画所有字的描边，再画所有字的填充，否则相邻字互相盖住。
- **英文用站酷快乐体**（库里自动选）：黄油体的 p 像 f。
- **缓存**：精灵和字形都有 `lru_cache`，参数里别传每帧都变的浮点数（比如 `t`），否则内存会涨。
- **改完先 `sweep.py`**，0 报错再渲染（它也检查重复镜头和回放）；渲染中途报错多半是某一帧坐标越界或除零。
- **像素字体缺字**：✔、∞ 之类的符号像素字体没有，会报“像素字体缺字”；换成汉字（对、未完待续）或用玻璃组件（高清字体）显示。
- **中文文件名**：上传后中文会变成 `_`，认歌时别把文件名当唯一依据。

- 简介写明“原唱：××｜像素二创 MV”。
- 故事、自编情节和梗已请用户确认。
- 3:4 竖版封面导出并看过（`scripts/cover.py`）：标题、原唱、署名不压主体，人物在画面中部。
