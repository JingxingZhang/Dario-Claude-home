# 先写故事，再画分镜（必读）

一支好看的 MV，观众看完能复述出“发生了什么”：谁，想要什么，遇到了什么，最后怎样了。
所以本 skill 不再逐句“把歌词画出来”，而是先从歌词里长出**一个有头有尾的故事**，再把每一句歌词放进故事的某个时刻里。
画面仍然要贴词：观众看任何一秒，都能从画面上认出正在唱的那句词。但这个画面同时也是故事往前走的一步。

故事写进项目里的 `故事.md`（模板：`templates/story_template.md`），和精读、分镜、角色设定一起在检查点交给用户。

## 为什么重复的歌词不能重复画面
流行歌的副歌通常会唱两三遍，主歌的旋律也会重复。如果每遍都放同一个镜头，观众第二遍就开始走神，故事也停在原地。
歌里的重复本来就不是原地踏步：同一句词，第一遍是期待，第二遍可能已经是回忆，第三遍可能是终于说出口。
**MV 的任务，是把这层“同词不同义”画出来。**
- 每一遍重复，都对应故事的一个新节拍：时间推进了、关系变了、地点换了、视角翻过来了，或者事件有了结果。
- 画面可以“押韵”：沿用同一个构图、同一个地点、同一个动作，让观众认出“这是那一句”。但人物状态、时间、天气、道具或结果一定要变，观众一眼就能看出“这次不一样了”。
- 旧版的“回放 + 弹幕”和“复用镜头换配色”都不再使用。`sweep.py` 会检查 SHOTS 里有没有重复的镜头函数。

## 写故事的步骤

### 1. 从主题和精读里找出故事的“种子”
先读 `歌词精读.md` 的结论（人设与关系、潜台词、转折句、被改动的字），回答：
- **主角想要什么？**（得到一个人、说出一句话、放下一段过去、回到一个地方……）
- **什么挡着他？**（不敢说、词穷、距离、时间、误会、自己）
- **最后怎样了？** 结局要顺着歌的最后一句，尤其是重复时被改动的那几个字走，不能反着改。
  例：《关键词》最后一遍把“让我见识爱情”改成“爱一个人爱得”，结局就该是主角终于亲手去爱，而不是还在旁观。
- 故事不能违背主题：暧昧的歌不能写成背叛，思念的歌不能写成“其实对方早就不在乎”。歌词里没有的坏人和反转，不要硬加。

### 2. 把故事切成和歌曲段落对齐的节拍
用歌曲结构当故事的骨架（时间来自 `tools/lyrics.txt` 和 `audio.json`）：

| 歌曲段落 | 故事作用 | 常见写法 |
|---|---|---|
| 前奏 | 开场：主角是谁、在哪、现在是什么状态 | 一个能代表“缺了什么”的画面 |
| 主歌一 | 起：日常被打破，遇见、发现或决定 | 交代人物关系和贯穿道具 |
| 导歌 | 承：靠近、犹豫、准备 | 把情绪往副歌推 |
| 副歌一 | 第一个高点：第一次心动、第一次说出口、第一次失去 | 画面最亮、动作最大 |
| 间奏 | 时间流逝或换地点 | 蒙太奇、季节变化、路上 |
| 主歌二 | 承：新的问题、更深的关系、更难的处境 | 不能只是主歌一换了衣服 |
| 副歌二 | 第二个高点：和副歌一同词，但处境已变 | 同构图不同结果，或换一个地点 |
| 桥段 | 转：真相、选择、低谷或顿悟 | 通常是故事的转折点，可以换一种画面语言 |
| 最后一遍副歌 | 合：结局，和第一遍副歌形成对照 | 把第一遍没做到的事做到，或接受做不到 |
| 尾奏、片尾 | 余韵：结局之后的一个安静画面 | 首尾呼应：回到开场的地方，但人已经变了 |

不是每首歌都有全部段落，按实际结构来。节拍表要写清：时间段、对应歌词、故事里发生了什么、情绪。

### 3. 给每一处重复写“新含义”
把所有重复出现的歌词（整句或大部分相同）列成一张表，每一遍各写一行：
- 这一遍在故事的哪个节拍；
- 这一遍画什么（地点、人物状态、动作、结果），和上一遍比**变了什么**；
- 为什么这句词放在这里仍然成立：同一句话在新处境里是什么意思。

常用的“同词不同义”手法（选适合这首歌的，别全用）：
- **时间推进**：同一个地点，第一遍是秋天初见，第二遍是冬天并肩，第三遍是第二年秋天。
- **关系推进**：第一遍隔着桌子，第二遍坐到同一边，第三遍牵手。
- **视角翻转**：第一遍从“我”的角度看，第二遍让观众看到“你”那一侧其实也在偷偷做同样的事。
- **想象 → 现实**：第一遍是主角脑子里的排练或幻想（可以用玻璃气泡、梦境配色），第二遍真的发生了。
- **结果揭晓**：第一遍提问或尝试（选择题、递出信），第二遍给出答案或回应。
- **角色互换**：第一遍主角为对方做的事，最后一遍由对方回赠。
- **回忆 vs 现在**：如果歌本身是回忆，前面几遍是回忆里的画面，最后一遍回到现在，主角独自（或终于不再独自）站在同一个地方。

### 4. 写成一段可以讲给别人听的故事
- **一句话梗概**（logline）：谁＋想要什么＋阻碍＋结局，一句说完。
- **故事正文**：300–600 字，按时间顺序讲，像讲给朋友听。要有具体的画面和动作，不要写“表达了思念之情”这种抽象的话。
- **人物小传**：每个角色一两句话：想要什么、怕什么、在故事里怎么变。
- **贯穿道具的成长线**：它在开头、中段、结尾分别是什么状态（例：开头是一页空白的笔记本 → 中段写满了划掉的词 → 结尾整本送给对方）。
- **自编情节**：歌词里没有、为了讲故事补的情节，单独列出，请用户确认。它只能放大精读里已有的意思，不能新造坏人、误会或背叛。

### 5. 自查
- 把歌词遮住，只看故事正文，能看懂吗？结局和开头比，有没有变化？
- 每一句歌词都能在节拍表里找到位置吗？每一处重复都有不同的画面吗？
- 故事和主题、精读一致吗？有没有用到精读里标为“要避开”的画法？
- 节奏重点句（转折、高潮）是不是正好落在故事的转折和高潮上？

## 故事怎么影响后面的步骤
- **视觉方案**：故事的时间线决定配色变化（季节、昼夜、天气），不再只是“第二遍副歌换一套色”。
- **角色设计**：角色要能体现变化，比如换季换装、道具从无到有、表情从拘谨到放开。
- **分镜**：逐句分镜表多一列“剧情节拍”，每句的画面先服务故事，再贴字面。
- **镜头代码**：按故事顺序写镜头函数；场景的绘制函数可以复用（同一条街、同一张书桌），镜头函数不复用。
- **封面**：选最能代表这个故事的一刻，不一定是最热闹的一帧。

## 例：《关键词》如果按新流程重做（示意）
旧版三遍副歌复用了同一组镜头，只换了午后、黄昏、清晨三套配色。按新流程，可以这样写：
- **一句话梗概**：一个总找不到合适词语的写字的人，用一个秋天学会把喜欢说出口，最后发现最好的词就是对方的名字。
- **副歌一**（“落叶的位置 谱出一首诗”）：主角第一次注意到对方，落叶在地上落成音符，主角在笔记本上记下第一个音。
- **副歌二**：同一棵银杏树下，两人一起捡落叶，对方把一片落叶夹进主角的本子。笔记本里第一次出现了另一个人的笔迹。
- **最后一遍副歌**：第二年秋天，主角把写满的笔记本送给对方。落叶在地上拼出的不再是音符，而是对方名字所在的位置。
- 三遍“你是我的关键词”：第一遍，搜索框里打出“你”；第二遍，主角终于当面念出这个词；第三遍，对方在本子最后一页写下主角的名字，作为回答（角色互换）。
