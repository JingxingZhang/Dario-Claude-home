# pixel-mv · 为每首歌定制、有完整剧情的像素 MV

**这个 skill 的目的**：从一首歌的**曲风**和**歌词**出发，先写一个只属于这首歌的**完整故事**，再把它拍成一支像素风 MV。
观众看完能复述出“发生了什么”，而且任何一秒都能从画面上认出正在唱哪句词。

- **要定制的**：故事、人物、配角、场景、配色、节奏、花字动效、玻璃元素，全部从这首歌里来。
- **不能套的**：没有默认主角、默认场景、默认剧情，也不沿用上一首歌的画面。
- **不能重复的**：重复的歌词不重复画面。每一遍重复都是故事的下一步（时间推进、关系推进、视角翻转、结果揭晓……），可以沿用构图做“视觉押韵”，但人物状态、时间或结果一定要变。
- **可以复用的**：素材库、脚本、范例只是工具和参考。

**不变的技术规格和署名约定**
- 16:9：原生 320×180 像素画，最近邻放大到 1920×1080，30 fps；画面全部用代码绘制，不用 AI 生成图片。
- **两层画面**：像素层画“世界”（人物、场景、道具、像素拟声词和印章）；液态玻璃层画“词和界面”（标签、气泡、弹窗、数值条、选择框、名字牌），直接画在 1080p 帧上，会折射底下的像素世界。引擎自动加歌词底部玻璃托盘、署名玻璃胶囊、段落透镜转场、柔光暗角。见 `references/liquid-glass.md`。
- 底部歌词是高清综艺花字。基调（回弹、逐字快慢、抖动）随曲风调整，重点词和配色随歌词选。
- 片头显示「歌名 + 原唱 · ×× + 像素 MV」，片尾再显示一次后淡出；底部居中常驻署名（`project.json` 的 `signature`，默认 `@张景行`）。
- 成片 ≤ 100 MB；封面两张：16:9（1920×1080）和 3:4（1080×1440）。

**用户已确认的规则**
1. 只在**故事、分镜和角色设定做完后停一次**，等用户确认再画；其余步骤一口气做完。
2. **先查创作背景、定主题，再逐句精读歌词，然后写故事，最后才分镜**（第 1.5 → 2.5 → 4 步）。人设、关系、贯穿道具、自编情节、结局都不能违背主题和精读结论。
3. **MV 是一个有剧情的完整故事**：有开场、发展、转折、结局，和歌曲的段落对齐（第 4 步）。
4. **重复的歌词不重复画面**：每一遍都要推进剧情。不再使用“回放 + 弹幕”或“复用镜头换配色”。
5. **主角、配角、场景都按故事定制**。主角的人数、年龄、时代、穿着、比例，甚至是不是人，都由歌词和故事决定；贯穿配角选一只宠物或一件代表物件，它也要有自己的成长线。
6. 只做 16:9 成片；封面另出一张 3:4 竖版。
7. 液态玻璃层是默认画风的一部分；用户明确要纯像素时，`MV(..., glass=False)` 关掉。
8. 表情包没有固定模板，用户要的时候按这首歌现做。
9. 成片不超过 100 MB。

设 `SK` 为本 skill 目录。

## 流程

### 0 · 环境（每个新会话先跑，约 1 分钟）
`bash $SK/scripts/setup.sh`：检查 ffmpeg 和 Python 依赖，下载三套 OFL 字体（像素字、花字黄油体、快乐体）。

### 1 · 收歌、认歌
- `ffprobe` 看时长和音视频流。
- **认歌名、原唱**：
  - 先看文件名。上传时中文会变成 `_`，数一下字数也有帮助。
  - 再用 2–3 句有辨识度的歌词搜索，交叉核对；歌词视频的片头常写着词曲信息。
  - 有翻唱时以首发 / 原唱为准，记下出处。认不出或来源矛盾 → 问用户。
- **顺便查曲风**：流派、编曲特点，供第 5 步使用。
- **新建项目**：`python3 $SK/scripts/new_project.py <项目目录> --audio <歌曲> --title 歌名 --artist 原唱`

### 1.5 · 创作背景与主题含义（先查再创作）
- **检索**（2–3 组关键词，中英文按需；记下来源和日期）：作词、作曲、编曲、发行时间、专辑或企划；词曲作者或歌手的访谈、发行文案；乐评和听众的主流解读。
- **分析主题含义**，写进 `分镜说明.md` 开头的「创作背景与主题」：
  - 一句话主题；谁对谁说、两人是什么关系、处在关系的哪个阶段；
  - **有歧义的词逐个列出**，写明采用哪种解读和依据；
  - 有官方说法以官方为准；只有听众解读时注明“听众解读”；查不到就写“我的理解”，并在检查点请用户确认。
- **主题是后面所有创作的前提**。不要从单个字眼推人设（比如看到“见异思迁”就把对方画成花心的人）。

### 2 · 歌词与时间 → `tools/lyrics.txt`
每行 `开始秒 | 结束秒 | 歌词`，`/` 表示花字换行。
- **带硬字幕的歌词视频**：
  1. 跑 `python3 $SK/scripts/lyrics_ocr.py <视频> <项目>/tools/ocr`。
  2. 先看 `band.png`，确认红框框住了字幕；不对就加 `--band 0.86,0.99` 之类。字幕很细时 320 宽检测会漏，`--color bright` 或自己在更高分辨率下切分。
  3. 用 Read 看 `lines_*.png`，把读出的歌词填进 `lyrics_skeleton.txt`，另存为 `lyrics.txt`。
- **Suno 歌曲**：用 `audio-lyrics-alignment` 拿逐字时间，按行合并。
- **LRC 文件**：`python3 $SK/scripts/lrc2lyrics.py 歌词.lrc tools/lyrics.txt --dur 时长`
- **只有纯文本**：按音量和段落估时间，并告诉用户这些时间是估的。

### 2.5 · 逐句歌词精读 → `歌词精读.md`
先读 `references/lyric-analysis.md`，按 `templates/lyric_analysis_template.md` 写。
- **通读**：谁对谁说；情绪从哪里起、哪句转折、落在哪里；重复段里被改动的字（往往是全曲的落点）。
- **逐句拆六层**：① 字面 ② 意象 ③ 修辞与双关 ④ 潜台词 ⑤ 在全曲的位置 ⑥ 可画的画面点 / 要避开的画法。
- **重复句**也要写：同一句在第几遍出现、前后语境变了什么。这是第 4 步“同词不同义”的原料。
- **有歧义的词单独成表**；**得出创作结论**：人设与关系、贯穿道具、节奏重点句、结局方向、不能出现的画法。

### 3 · 音频分析 → `tools/audio.json`
`python3 $SK/scripts/audio_analyze.py <歌曲> <项目>/tools/audio.json`：逐帧音量、BPM、每拍时刻。

### 4 · 故事设计 → `故事.md`（新的核心步骤）
先读 `references/story-design.md`，按 `templates/story_template.md` 写。
- **一句话梗概**：谁 + 想要什么 + 阻碍 + 结局。结局顺着最后一句（和被改动的字）走。
- **人物**：每个角色想要什么、怕什么、怎么变；贯穿配角或道具的成长线（开头 → 中段 → 结尾）。
- **故事正文**：300–600 字，按时间顺序，写具体的画面和动作，像讲给朋友听。
- **节拍表**：把故事切成和歌曲段落对齐的节拍。前奏开场；主歌一起；副歌一第一个高点；主歌二承；副歌二第二个高点；桥段转；最后一遍副歌是结局；尾奏余韵、首尾呼应。
- **重复歌词的新含义表**：每一处重复、每一遍一行。写这一遍画什么、和上一遍比变了什么、这句词在这里的意思。
- **自编情节**单独列出，请用户确认。只能放大精读里已有的意思，不能新造坏人、误会、背叛。
- 自查：遮住歌词能看懂故事吗？每句词都有位置吗？每处重复都有不同的画面吗？

### 5 · 视觉方案 + 角色设计 + 分镜 ⏸ 停下给用户看
以 `故事.md` 和 `歌词精读.md` 为依据，依次读 `references/visual-design.md`（曲风 → 视觉）、`references/liquid-glass.md`（玻璃层）、`references/storyboard-guide.md`（逐句分镜），然后做三件事：

1. **视觉方案**，写进 `分镜说明.md`：曲风判断 → 剪辑节奏、动作幅度、花字基调；世界（时代、地点、季节、天气）；**配色随故事的时间线变化**（季节、昼夜、天气），并写明理由；角色比例；哪些东西用玻璃层表现。
2. **角色设计**：在 `mv.py` 里用 `charkit.pixmap` 字符画从零画。每个角色至少画站立、一个最关键的动作、4–6 种表情；故事里角色会变（换季换装、道具从无到有），就把变化后的样子也画出来。写 `CAST_SHEET(img, t)`，用 `python3 $SK/scripts/cast_sheet.py <项目> <项目>/cover/角色设定.png --gif` 导出设定图。
3. **逐句分镜表**：每句写 6 格：剧情节拍｜场景｜人物动作和表情｜画面内像素字与玻璃元素｜配角和物件反应｜为什么贴这句（引用精读和故事）。另写前奏、间奏、桥段、尾奏、片尾，以及段落切换时刻（`SECTIONS`，透镜转场用）。

用 SendUserFile 发 `故事.md`、`歌词精读.md`、`分镜说明.md` 和 `角色设定.png / .gif`。在对话里按这个顺序概括：
- **主题解读**（附来源）；
- **故事梗概和结局**；
- **重复歌词怎么推进剧情**（每处重复各一句）；
- **精读关键结论**：转折句，有歧义的词采用了哪种读法；
- **视觉方案和玻璃元素的亮点**；
- **自编情节**清单。

**等用户确认或修改后再继续。**

### 6 · 写镜头 → `mv.py`
- **先读的资料**：`references/library-api.md`（工具速查，含 glassui）、`references/huazi-style.md`（花字规则）；拿不准写法时看 `examples/huxi-jueding/mv.py` 怎么组织代码，但不照搬画面。那个范例是旧流程，用了回放，不要学它的重复段写法。
- **镜头写法**：
  - 按故事顺序写镜头函数 `fn(img, t, lt, v)`，动作按 `lt` 编排，节奏按视觉方案来：抒情少切慢动，快歌多动作点、踩拍。
  - **场景绘制函数可以复用**（同一条街、同一张书桌），**镜头函数每个只用一次**。重复的歌词写新的镜头函数，画剧情的下一步。确需首尾呼应地复用同一函数，写进 `ALLOW_REPEAT` 并说明理由。
  - 玻璃元素用 `glassui` 组件登记（`gtag`、`say`、`gcard`、`gmove`……），born 踩在拍点或重点词上。
- **镜头表 `SHOTS`**：用 `L(i)` 对齐第 i 句。**`SECTIONS`** 列出段落切换时刻，传给 `MV(..., sections=SECTIONS)`。
- **花字配置**：`LYRIC_BASE` 写曲风基调，`TITLE_STYLE` 写片头歌名样式，`CFG` 为每句选配色、重点词、贴纸。重复的歌词可以按剧情换重点词和配色（键用句序号）。
- **封面**：写 `COVER_T`（16:9 取哪一秒）和 `COVER_3X4(img, t)`（3:4 竖版的像素层，180×240，见模板）。

### 7 · 检查（循环到干净为止）
1. `python3 $SK/scripts/sweep.py <项目>`：全片扫错，同时检查有没有重复使用的镜头函数和回放镜头，必须 0 报错。
2. `python3 $SK/scripts/still.py <项目> <拼图.png> 秒,秒,…`：导关键帧拼图，覆盖每句中段、动作点、片头、间奏、片尾、段落转场。用 Read 逐张看，对照 `references/pitfalls.md`。
3. **把重复歌词的几帧并排放在一张拼图里看**：一眼就能看出“这次不一样了”吗？
4. 关键玻璃元素用 `mv.frame(秒).crop(...)` 截全分辨率局部看：字清不清楚、折射和高光是否明显。

第 0 条最重要：这些画面换到别的歌上也说得通吗？说得通就是还在套模板，要重做。

### 8 · 渲染（后台，10–15 分钟）
`python3 $SK/scripts/render.py <项目>`（`--from/--to --draft` 出小样）。
- 玻璃层每帧多花约 0.3–0.5 秒，开工时告诉用户大概要多久。
- 自动配原曲，体积 ≤ 100 MB，超了会自动改两遍编码。
- 完成后从成片里抽 6 帧复看，确认时长一致。

### 9 · 交付
- **封面**：`python3 $SK/scripts/cover.py <项目>` 导出 `cover/封面_16x9.png` 和 `cover/封面_3x4.png`，Read 看一遍再发。
- **用 SendUserFile 发**：成片 MP4、两张封面、`故事.md`、`歌词精读.md`、`分镜说明.md`、角色设定图。
- **发布建议**（写进 `发布建议.md`）：
  - 3–4 个抖音标题，每个说明理由；首选歌名在前，加一个片中真实存在的钩子，故事的悬念最好；
  - 简介写明「原唱：××｜像素二创 MV」，可以附一句故事梗概；
  - 话题；置顶评论的互动问题。
- **推送**：代码和文稿推送到仓库，成片和原曲不进仓库。

### 附 · 互动表情包（用户要时才做）
1:1，内容按这首歌定制：用 MV 里的角色、贯穿配角和标志道具，配一个“操作”和前后两个状态。
- 写法：`templates/sticker_template.py` + `lib/sticker.py`，最后 `Sticker(...).export()`。
- 产出：480×480 GIF（2.4 秒循环）+ 两张 1080×1080 静图。默认不加署名。`examples/stickers/` 只作参考。

## 底线
- 画面全部用代码绘制，不用 AI 生成图片，不模仿现成影视、动漫、游戏的具体画面或角色。液态玻璃只借鉴材质和动效，不出现 Apple 的标志、界面截图或产品名。
- 歌名、原唱要核实；简介注明原唱和二创，不写成或暗示是官方作品。成片和原曲不进公开仓库。
- 故事和画面里编的情节、梗要标出来给用户确认；不碰真人负面信息；不给“我”“你”编真实姓名。
- 歌词只用用户提供或从用户文件里读出的，不凭记忆补全。
- 长任务放后台跑，并告诉用户大概要多久。

## 目录
- `scripts/`：
  - `setup.sh`、`fonts.py`：环境和字体；
  - `new_project.py`：新建项目，附带故事、精读、分镜模板；
  - `lyrics_ocr.py`、`lrc2lyrics.py`：歌词与时间；
  - `audio_analyze.py`：音频分析；
  - `cast_sheet.py`：角色设定图；
  - `sweep.py`：全片扫错 + 重复镜头检查；`still.py`：关键帧拼图；
  - `render.py`：渲染；`cover.py`：16:9 与 3:4 封面。
- `lib/`：
  - `charkit`：角色设计，字符画精灵、眼睛、嘴、配色条；
  - `pixlib`：底层，像素字、抖动渐变、天空水面；
  - `props2`：像素综艺元素、会演戏的物件、宠物、场景道具；
  - `chars`：小道具、背景特效，以及 Q 版小人脚手架；
  - `scenes_common`：霓虹街、雨、窗边；
  - `glass`：液态玻璃材质（折射、色散、游走高光、投影、弹簧动效、柔光暗角）；
  - `glassui`：玻璃组件（标签、气泡、提示卡、数值条、搜索框、选择框、心形窗、透镜、水珠）；
  - `huazi`：花字；`cover`：3:4 封面构图；
  - `engine`：镜头表、歌词、片头片尾、署名、高清玻璃合成、段落透镜转场；
  - `sticker`：表情包。
- `templates/`：`mv_template.py`（只有骨架，没有默认角色）、`story_template.md`（故事）、`lyric_analysis_template.md`（歌词精读）、`storyboard_template.md`（分镜说明）、`sticker_template.py`。
- `references/`：
  - `story-design.md`：先写故事、重复歌词怎么推进剧情，必读；
  - `lyric-analysis.md`：逐句歌词精读，必读；
  - `visual-design.md`：曲风 → 视觉，必读；
  - `liquid-glass.md`：液态玻璃层的设计与用法，必读；
  - `storyboard-guide.md`：逐句分镜，必读；
  - `library-api.md`：工具速查；`huazi-style.md`：花字规则；`pitfalls.md`：检查清单。
- `examples/`：`huxi-jueding/`（《呼吸决定》，旧流程的代码组织参考：用了回放，没有玻璃层，不要学它的重复段）、`stickers/`。
