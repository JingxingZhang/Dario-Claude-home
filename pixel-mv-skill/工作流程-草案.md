# 像素综艺 MV · 工作流程（草案，供审阅）

> 依据：《呼吸决定》像素 MV 第二版的实际做法整理而成。审阅通过后，再按此做成可一键调用的 skill。
> 文中「⚑ 待确认」是需要你拍板的地方，汇总在最后一节。

---

## 一、这个 skill 做什么

**输入**：一首歌（mp4 / mp3 / wav；带字幕的歌词视频最好），可选：歌词文本、Suno 歌曲链接、想要的风格或角色。
**输出**：一支像素风 + 综艺花字的 MV 成片，外加封面、分镜说明和发布建议。

**风格固定为**：
- 画面：原生 320×180 像素画，最近邻放大到 1920×1080，30 fps；全部用代码绘制，不用任何 AI 生成图片。
- 底部歌词：高清综艺花字（粗圆体、多层描边、渐变填充、逐字弹跳、重点词放大换色、贴纸）。
- 画面内也“综艺”：像素拟声词、印章、内心 OS、系统消息、复古弹窗、数值条、弹幕。
- 配角会演戏：一只橘猫全程吐槽；月亮、路灯、垃圾桶、闹钟、手机、楼房等都带表情。
- 片头显示「歌名 + 原唱」，片尾再显示一次；底部居中常驻署名「@张景行」。

**要说清楚的一点**：「一键」指的是流程一键跑完。但每首歌的分镜和场景，仍然是 Claude 读懂歌词后现写的代码。skill 提供的是素材库、模板、检查清单和渲染管线，而不是一个套模板的生成器。这样每首歌的画面才能贴合歌词，代价是每首要花一段时间（见第四节）。

## 二、完整流程（10 步）

### 第 0 步 · 环境准备（每个新会话自动执行，约 1 分钟）
- 检查 ffmpeg、Python（Pillow / numpy / fontTools / brotli）。
- 下载并缓存三套 OFL 授权字体：
  - Fusion Pixel 12px：像素字，用于画面内文字；
  - 站酷庆科黄油体：中文花字；
  - 站酷快乐体：英文和小标签。
  三套都从 jsDelivr 上的 npm 包下载。

### 第 1 步 · 收歌、认歌
- 读取上传文件的时长、音视频流，抽出音轨。
- **认歌名和原唱**：先看文件名；再用 2–3 句有辨识度的歌词搜索，交叉核对。有翻唱版本时，以首发 / 原唱为准，并写明出处。
- 认不出来，或来源互相矛盾 → 停下来问你。

### 第 2 步 · 拿歌词和时间（按可用程度自动选一种）
| 来源 | 精度 | 做法 |
|---|---|---|
| A. Suno 歌曲 | 逐字 | 调歌词对齐接口，拿每个字的起止时间 |
| B. 带硬字幕的歌词视频（这次用的） | 逐行，约 0.1 秒 | 每秒抽 10 帧，比较字幕区域的变化，切出每行字幕的起止时间；再把每行截图拼图，由 Claude 看图读字 |
| C. 你提供的 LRC 或歌词文本 | 逐行 | LRC 直接用；纯文本则结合音量起伏估算时间，请你抽查几句 |

产出 `lyrics.txt`，每行格式：`开始秒 | 结束秒 | 歌词`，用 `/` 表示花字换行。
⚑ 方式 C 估出来的时间不准，是否必须让你确认后再继续？

### 第 3 步 · 音频分析
- 逐帧算音量（RMS），估节拍（BPM 和每拍时刻），写入 `audio.json`。
- 用途：花字重点词随鼓点弹跳；心跳、波形、霓虹灯的闪动跟着音乐走。

### 第 4 步 · 读懂歌（歌曲说明）
写一页简短的歌曲说明：
- 谁在对谁说话、整首讲了什么、情绪在哪里转折；
- 段落结构：前奏、主歌、副歌、间奏、重复段、尾奏；
- 每段一句话的“戏眼”。

### 第 5 步 · 分镜（核心步骤）⚑ 建议在这里停一次给你看
逐句设计。每一句必须写清 5 项：
1. **场景**：街、室内、天台、审讯室、片场、海边……
2. **人物的动作和表情**：主角两人；表情和动作库见附录 A。
3. **画面内像素花字**：拟声词、印章、OS、系统消息、弹窗、数值条，任选。
4. **配角和物件的反应**：猫、月亮、路灯等。
5. **和歌词的对应关系**：用一句话说明这一镜为什么贴这句词。

另有几条结构规则：
- **前奏**：标题卡（歌名 + 原唱），然后用 2–3 个镜头交代人物和场景；前奏超过 12 秒时，画面必须一直有动作。
- **间奏**：做一段“回忆”或“情绪”戏，比如回忆相片、雾上画心。
- **重复段**：第二遍主歌加「回放 REPLAY」标签、褪色扫描线和弹幕；第二遍副歌整体换配色；最后一句可以改写结局。
- **尾奏**：给一个情绪落点，比如雨停、天亮、彩虹；片尾卡显示歌名 + 原唱 + 谢谢收看。
- **画面里自己编的梗**（比如“小美：宝贝晚安”）在分镜表里标出来，方便你删改。

产出：`分镜说明.md`，一句一行的表格。

### 第 6 步 · 歌词花字配置
每句定这几项：配色（粉、黄、青、红、紫、绿、白）、重点词及其颜色、字号、倾斜角度、贴纸（爱心、星星、叹号、问号、汗滴、叉、音符、闪电、雨滴、恶魔角）、位置（默认在下方，个别句子放到上方）。

### 第 7 步 · 写场景代码
- 用素材库：`pixlib`（底层）、`chars`（人物）、`props2`（综艺素材和会演戏的物件）、`huazi`（高清花字）。
- 每个镜头写成一个函数，所有动作都按「这句开唱后第几秒」编排。这样重复段直接复用，第二遍改配色或加回放效果即可。
- 素材库里没有的东西，就在本歌的文件里按同样写法补画；通用的部分回收进素材库，下一首就能直接用。

### 第 8 步 · 关键帧检查（循环到没有问题为止）
先把每句中段、每个动作点、片头、片尾导出拼图，Claude 逐张看，对照检查清单（附录 C）修改。修完再导一遍，直到没有问题。

### 第 9 步 · 渲染成片（后台，约 2–5 分钟）
- 4 个进程并行出帧 → H.264（CRF 18，High profile，+faststart）。
- 音轨用原曲：从上传的文件里取，转成 AAC 192k。
- 质检：时长与原曲一致（±0.1 秒）；全片逐帧扫描无报错；从成片里抽 6 帧复看。

### 第 10 步 · 交付
- 成片 MP4、16:9 封面（取最有戏的一帧）、`分镜说明.md`。
- 发布建议：3–4 个抖音标题，每个说明选它的理由；简介里写明“原唱：××｜像素二创 MV”；话题；置顶评论的互动问题。
- 推送代码和文稿。成片、字体、原曲音频不进仓库。

### 附加 · 互动表情包（可选，⚑ 是否纳入 skill）
提供 1:1 模板：关注领原视频、感谢关注求推荐、关注优先定制下一首。
- 每个出一张 480×480 的 GIF（2.4 秒循环），和两张 1080×1080 的静图（操作前 / 操作后）；
- 可改文案和配色；不带署名。

## 三、skill 的文件结构（草图）

```
pixel-mv/
├── SKILL.md                    流程、默认设置、底线（本文件精简版）
├── scripts/
│   ├── setup.sh                装依赖、下字体
│   ├── lyrics_ocr.py           从歌词视频切字幕行 + 出拼图
│   ├── audio_analyze.py        音量、节拍
│   ├── still.py                关键帧拼图
│   ├── render.py               并行渲染 + 配原曲
│   └── sticker.py              表情包模板
├── lib/
│   ├── pixlib.py  chars.py  props2.py  huazi.py  scenes_common.py（街、室内、雨、天台等通用背景）
├── templates/
│   ├── mv_template.py          镜头表骨架、花字配置骨架、回放 / 换色机制
│   └── 分镜说明模板.md
└── references/
    ├── storyboard-guide.md     逐句分镜的思路、元素库、好坏例子（以《呼吸决定》为范例）
    ├── huazi-style.md          花字配色、重点词、贴纸规则
    └── pitfalls.md             踩过的坑（见附录 C）
```

**调用方式**：上传歌曲后说“用像素 MV 做这首”，或输入 `/pixel-mv`。

## 四、耗时预估（一首 4 分钟左右的歌）

| 步骤 | 时间 |
|---|---|
| 环境、收歌、认歌、歌词时间 | 5–10 分钟 |
| 歌曲说明 + 分镜 | 10–15 分钟（如果停下等你审，加上你看的时间） |
| 写场景代码 + 关键帧检查 2–3 轮 | 30–50 分钟 |
| 渲染 + 质检 + 交付 | 5–10 分钟 |
| **合计** | **约 1 小时**，其中你只需要看分镜那一次 |

## 五、附录

### A. 现有素材库（skill 里直接可用）
- **人物**（女主、男主）：
  - 表情：微笑、眨眼、坏笑、脸红、害羞、心形眼、斜眼、生气、噘嘴、难过、惊讶、闭眼；
  - 动作：挥手、指、比心、耸肩、捂脸、侧耳、拿手机、打伞、单膝跪、握拳、捂胸口、走路、呼吸起伏；
  - 配件：墨镜、面具、恶魔角。
- **橘猫**：坐、走、睡、哈气、打滚、举牌；表情有斜眼、惊讶、开心、心形眼、生气、捂眼；可戴警帽、风镜、墨镜。
- **会演戏的物件**：月亮、太阳、路灯、垃圾桶、闹钟、日历、手机、心、楼房；可用表情有开心、震惊、难过、斜眼、睡、脸红、坏笑、尖叫、大笑、心形眼。
- **场景和道具**：霓虹雨夜街（可卷动）、窗边室内、天台、审讯室、T 台、舞台幕布、海边、山、游乐园摩天轮、情绪老虎机、情绪表盘、心电波形、电驴、保险箱、打板、评分牌、喇叭、烟花、彩虹、信封、玫瑰、放大镜。
- **像素综艺元素**：拟声词、印章、OS 气泡、对话气泡、系统消息、复古弹窗加鼠标、数值条、开关、弹幕、黑边“特写”、集中线、放射背景。

### B. 默认设置（⚑ 请确认）
| 项 | 默认 |
|---|---|
| 画幅 | 16:9 横屏 1920×1080 |
| 署名 | 底部居中「@张景行」，表情包不加 |
| 片头 | 歌名 + 「原唱 · ××」 + 「像素 MV」 |
| 主角 | 每首按歌词定（男女、两个女生、一个人都行）；**橘猫作为系列吉祥物固定出现** |
| 画面内编的梗 | 允许，但在分镜表里标出 |
| 成片体积 | 不设上限，通常 80–90 MB；可加上限，例如 ≤ 100 MB |

### C. 检查清单（来自这次踩过的坑）
1. 小号像素字（12 px）只描一圈深色边；加白色内描边就糊。
2. 花字要分两遍画：先画所有字的描边，再画所有字的填充，否则相邻字会互相盖住。
3. 英文用站酷快乐体：黄油体的 p 看起来像 f。
4. 画面内的像素字和道具放在原生 y < 120 的范围，避开底部歌词花字和署名。
5. 人物的朝向、风向、船或车的运动方向要一致。上次火船逆风就被我改过。
6. 比心之类的手臂动作要绕开脸，不能从脸上穿过去。
7. 打字机效果的气泡在刚出现那一刻只有一个字，检查时别误判成 bug。
8. 重复段一律用相对时间（这句开唱后第几秒），不要写死绝对秒数。
9. 每次改完都要全片逐帧扫一遍，捕获越界之类的报错，再渲染。
10. 原曲版权：简介里写明原唱，并说明是二创；成片、原曲音频不进仓库。

## 六、⚑ 需要你拍板的问题

1. **停几次给你看？**
   - 建议：只在分镜完成后停一次。
   - 备选：全自动不停；或者认歌和歌词完成后再多停一次。
2. **主角怎么定？**
   - 建议：每首按歌词定主角，橘猫固定出现。
   - 备选：女主、男主、橘猫这一套固定不变，做成系列感。
3. **要不要支持 9:16 竖屏？**
   - 支持的话，构图要另做一套，工作量 +30%。
4. **表情包模板要不要纳入这个 skill？**
   - 或者单独做一个 skill。
5. **skill 名称**：建议 `pixel-mv`（像素综艺 MV），你也可以起中文名。
6. **成片要不要设体积上限？**
